## Pankaj Kumar · GTM engineer

**Slot:** on slot today with the n8n post · this one for **Tue 24 Nov · 22:30 IST** (09:00 PT), ten days before the deadline · **Pillar:** Changelog reads · **Archetype:** technical truth-teller · **Rung:** 3 (changelog announced earlier; deadline Dec 4; migration PR closed Nov 16)

### Research brief
- **What's changing:** HubSpot sunsets the Pipelines API v1 on December 4, 2026; v1 calls stop working after that date. HubSpot recommends the 2026-09 version of the Pipelines API (GA Sept 9, 2026; 2026-03 or newer also avoids disruption). One third-party guide says Nov 2; HubSpot's changelog says Dec 4, and the post follows HubSpot.
- **The wiring detail (Airbyte's migration PR, opened):** old endpoint `GET https://api.hubapi.com/crm-pipelines/v1/pipelines/{objectType}`; the PR moved to `/crm/v3/pipelines/{objectType}`, and Airbyte's master has since moved the stream to the 2026-09 Pipelines API. Response changes listed: `pipelineId` and `stageId` become `id`; `active` becomes `archived`, which is true when the pipeline or stage is not active; `createdAt` and `updatedAt` change from epoch milliseconds to ISO 8601 strings.
- **The collision:** HubSpot froze edits to Node.js 20 custom code actions on Nov 17, 2026 (Pankaj's Nov 10 post). A v1 call inside a Node.js 20 action can't be fixed in place; the action has to be rebuilt on Node.js 24.
- **Sources:** [HubSpot changelog](https://developers.hubspot.com/changelog/pipelines-api-v1-sunset) (blocked here) · [Airbyte PR #89936](https://github.com/airbytehq/airbyte/pull/89936) (opened) · [HubSpot Node.js runtime changelog](https://developers.hubspot.com/changelog/sunsetting-design-manager-serverless-functions-and-older-node.js-runtimes-for-custom-code-actions)
- **Why it matters to the reader:** stage lists feed forecast syncs, routing and reporting. A sync that maps `active` straight onto `archived` won't error. It will just mark every live stage as archived.
- **Angle:** the path change is easy; the flipped boolean is the trap. Find the calls, invert the flag, convert the timestamps, rebuild frozen Node 20 actions, diff before switching.

### Post
<!-- post:pankaj format:single-image ask:sharp-question type:news -->
HubSpot Pipelines API v1 stops answering on December 4.

HubSpot's changelog says v1 calls stop working after that date, and points to the 2026-09 version of the Pipelines API.

Anything that reads stages from /crm-pipelines/v1/pipelines goes quiet that day. Stage mappings, forecast syncs, routing that checks the stage list.

The path change is the easy part. The payload is where it bites.

When Airbyte moved its HubSpot connector off v1, its pull request listed the changes:

↳ The fields pipelineId and stageId become id.

↳ The active flag becomes archived, and its meaning flips: archived is true when the stage is not active.

↳ The createdAt and updatedAt timestamps go from epoch milliseconds to ISO 8601 strings.

Map active straight onto archived and nothing errors. Every live stage just reads as archived.

What I'd run before December 4:

1. Search your code, n8n HTTP nodes, Zapier and Make steps for crm-pipelines/v1.
2. Move each call to the 2026-09 Pipelines API. Check the path against HubSpot's reference.
3. Invert active into archived in every mapping, and convert the timestamps.
4. If the call sits in a Node.js 20 custom code action, you can't edit it anymore. HubSpot froze those edits on November 17, so rebuild the action on Node.js 24.
5. Diff one pipeline's stages from the old and new responses before you switch over.

Rename a field and a sync breaks loudly. Flip a field and it breaks quietly.

Which of your syncs still reads stages from v1?
