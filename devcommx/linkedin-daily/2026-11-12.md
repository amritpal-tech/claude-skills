### Post
<!-- post:pankaj format:single-image ask:sharp-question type:news -->
One HubSpot setting decides what Claude can change.

On November 10, Anthropic made HubSpot one of the first apps that opens inside Claude. You work the pipeline beside the chat, and Claude acts on tasks and follow-ups while you approve the changes.

Through HubSpot's connector, Claude can already update deal stages, log notes and create tasks.

The setting is Write tools. HubSpot's own guidance is to set them to Needs Approval, so a human confirms every change.

Here's the plumbing I'd check before anyone turns it on:

1. Write tools on Needs Approval, for everyone, until you've read a week of changes.
2. Audit log. Writes are attributed to both the user and the Claude connector. Build a weekly report on them.
3. Stage rules. One implementation guide warns that pipeline stage and association label validations don't run on connector writes. Test it in a sandbox before you trust it.
4. Required fields. If a stage depends on a field being filled, add a workflow that checks it after the change.
5. Deletes. The connector doesn't support them. Keep it that way in anything you build on top.

Here is the line that splits this room: if a rule only lives in the UI, the agent never sees it.

Move the rules from the screen into the data.

Which of your HubSpot rules only live in the UI?
