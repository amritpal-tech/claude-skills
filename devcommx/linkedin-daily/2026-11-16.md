### Post
<!-- post:pankaj format:text ask:repost-if type:news -->
Claude Code shipped five security fixes in five days.

If your GTM agents run in it, against your CRM over MCP, read this before the next unattended run.

From the release notes, November 9 to 13:

↳ MCP OAuth requests could send secrets such as refresh tokens to another host when a server redirected them.

↳ The Write and Edit tools could write to a path covered by a Read deny rule.

↳ Bash deny and ask rules missed some commands run through sudo, env and similar wrappers.

↳ Some compound Bash commands could run without asking.

↳ Relative deny rules like Read(./.env) stopped covering the project after a cd.

All fixed in 2.1.321 to 2.1.325. Only if you update.

What I'd do before the next run:

1. Check claude --version. Update to 2.1.325 or later.
2. Re-read your allow rules. A new start-up warning flags rules with a * inside a variable's value.
3. Test your deny rules from a subfolder, not only from the project root.
4. For unattended runs, set permissions.denyInsteadOfPrompting. A blocked call is denied and the run moves on instead of waiting.
5. List which MCP servers hold CRM tokens. If you can't say whether one redirects, rotate its tokens.

Here's the uncomfortable part: an agent's permissions are only as current as your last update.

Guardrails are a version number. Check yours.

Repost if your agents touch the CRM with nobody watching.
