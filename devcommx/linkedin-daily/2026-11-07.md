### Post
<!-- post:amritpal format:text ask:save-this type:evergreen -->
Search Console's AI report has no clicks in it.

Since August 31, Google's generative AI performance report has been available to sites worldwide. It covers AI Overviews and AI Mode, plus generative features in Discover.

It shows impressions by page, country and date. It doesn't show clicks, CTR, queries or position. The data starts on May 18, with no backfill.

That's a thin report. It's also the only first-party AI visibility data Google gives you, so here's how I'd read it:

1. List your top 20 pages by AI impressions. These are the pages Google's AI is using when it answers about your category.
2. Put them next to the same pages' organic clicks. High AI impressions with falling clicks means the answer is being read on Google, before anyone reaches your site.
3. Rewrite those pages answer-first, with your brand name in the opening paragraph, so whatever gets quoted carries it.
4. Split by country and device before you draw conclusions. AI features don't roll out evenly.
5. Start a monthly baseline now. Without history, you can't tell a trend from a rollout.

One honest limit: impressions are views, and Google publishes no threshold for when a site gets the report at all.

A report without clicks still tells you where you're being read.

Save this for your next search review.

### Research brief
- **The anchor facts (as reported):** HubSpot's remote MCP server became generally available on Apr 13, 2026 with OAuth 2.1; one source says its writes respect the connected user's HubSpot permissions, another describes a read-only launch state. Cognism's MCP is read-only and governed by existing account settings, available to Standard and Pro customers since September 2026 (Cognism's own blog). - **Sources:** [Cognism blog](https://www.cognism.com/blog/mcp-server-commands-gtm) · [Cognism on MCP vs API](https://www.cognism.com/mcp-api) · [Amplemarket comparison of sales MCP servers](https://www.amplemarket.com/blog/best-mcp-servers-for-sales) (via search summaries; vendor docs not opened)

### Post
<!-- post:pankaj format:carousel ask:save-this type:evergreen -->
Every MCP connection is a new user in your CRM.

Most GTM tools now ship an MCP server. HubSpot's remote server went GA in April with OAuth 2.1. Cognism's is read-only and follows your existing account settings. Attio's hosted server takes OAuth only, no API keys.

So the real question is what each connection is allowed to do. Read access can leak data. Write access can rewrite history.

Here's the rollout order I'd use:

1. Read-only first. Let the agent prove it reads the right records before it writes any.
2. Per-user auth over shared keys. An agent acting as "the integration user" can see everything and owns nothing. When it breaks something, you can't tell whose request did it.
3. Scope the tools. Switch off every write tool you won't need this quarter.
4. Log every tool call: who, which record, what changed, which prompt asked for it.
5. Writes behind approval. A human confirms the first hundred, then you decide.

Honest limit: vendor docs change fast and tell slightly different stories about write access. Check each server's current docs before you connect it.

An agent with a shared admin key is the most privileged user you never interviewed.

Save this before you connect the next one.
<!-- /post -->
