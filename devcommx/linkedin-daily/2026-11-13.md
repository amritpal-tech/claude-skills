**Slot:** banked for **Mon 16 Nov 22:30 IST** (09:00 PT) · **Pillar:** data truth & RevOps mechanics · **Archetype:** technical truth-teller · **Rung:** 3 (HubSpot change from Oct 30, labelled "late October")

### Research brief
- **What changed (HubSpot release notes, via an aggregator):** around Oct 30, "Calculated enumeration properties: Calculation properties can now output dropdown values."
- **HubSpot's KB (via search summary):** the calculation properties guide (recently updated) lets you choose Enumeration as the output type for a custom equation; values in the expression must match the internal name of an option. The Properties API accepts type `enumeration` for `calculation_equation` fields.
- **Third-party detail:** enumeration values in equations are treated as strings and wrapped in double quotes.
- **Plan:** calculation properties have been a Professional and Enterprise feature; the source for that is old, so it's a verify line, and the post only says to check your tier.
- **Sources:** [HubSpot KB: calculation properties](https://knowledge.hubspot.com/properties/create-calculation-properties) · [HubSpot Properties API](https://developers.hubspot.com/docs/api-reference/crm-properties-v3/guide) (via search summaries; releasebot.io and HubSpot hosts blocked here)
- **Why it matters to the reader:** RevOps teams keep workflows whose only job is to set a dropdown (tier, region, SLA bucket). A computed field removes the enrollment logic that drifts.
- **Angle:** if a value can be computed, compute it in the field.

### Post
<!-- post:pankaj format:text ask:save-this type:news -->
Plenty of HubSpot workflows exist only to set one dropdown.

Lead tier from a score. Region from a country. SLA bucket from a deal amount.

In late October, HubSpot shipped a quiet change: calculation properties can now output dropdown values. Its knowledge base lists Enumeration as an output type for custom equations.

So a field can work out its own picklist value, without a workflow.

Why that matters for the plumbing:

↳ A workflow sets the value when a record enrolls, and again only if re-enrollment is on. A calculation updates when its inputs change.

↳ Fewer workflows means fewer enrollment triggers to drift out of date.

↳ Views, reports and routing read the result like any other dropdown.

Here's how I'd use it:

1. List the workflows whose only action is setting one dropdown.
2. Rebuild one as a calculation property with an Enumeration output. The values in the formula must match each option's internal name exactly.
3. Run both side by side for a week and compare the values on every record.
4. Switch the workflow off only when they match.

Honest limit: calculation properties aren't on every HubSpot tier. Check yours before you plan around it.

Here is the line that splits this room: a workflow that only sets a field is a field pretending to be logic.

Save this for your next workflow audit.
<!-- /post -->
