### Research brief
- **What happened:** Search Engine Roundtable reported on Nov 2, 2026 that Google moved AI Overviews for many brand searches from the top or middle of the main results into the right-hand column on desktop, the slot knowledge panels have used. Examples: [apple], [zillow], [coca cola], [google], [search engine roundtable], all US results. Barry Schwartz called it "essentially replacing brand knowledge panels with AI Overviews."
- **Context:** Ahrefs measured AI Overviews on 82.91% of US desktop results for branded keywords as of Sep 29, 2026. Separately, ppc.land reports Google's Performance Max help page now says PMax "may filter out navigational and brand-specific searches in favor of dedicated brand Search campaigns."
- **Sources:** [Search Engine Roundtable, Nov 2](https://www.seroundtable.com/google-ai-overviews-brands-right-42440.html) (secondary; Google has not announced it, so there is no primary) · [Ahrefs study](https://ahrefs.com/blog/ai-overviews-on-branded-searches/) · [ppc.land](https://ppc.land/google-moves-ai-overviews-for-brand-searches-out-of-the-main-results/)
- **Why it matters to his reader:** the right rail of a brand search used to be structured facts a marketer could influence (Knowledge Graph, Business Profile). An AI Overview summarises whatever pages the model trusts about the brand, so the most visible spot on a brand's own SERP becomes a citation problem.
- **What the sources do not say:** whether it is a test or a rollout, mobile behaviour, regions outside the US, or any click impact. The post does not claim any of it.

### Post
<!-- post:sumit format:text ask:sharp-question type:news -->
70 platforms. One playbook format. No vendor owns it.

On October 22, Anthropic handed Agent Skills to the Agentic AI Foundation, the Linux Foundation group that already looks after MCP.

A skill is a folder with a SKILL.md file that teaches an agent one job.

Per Anthropic, 70+ agent platforms have integrated the format since December 2025. ChatGPT, Cursor, GitHub Copilot and VS Code among them.

Here's why a GTM leader should care.

Most AI SDR contracts sell you a black box. The research steps, the qualification rules, the messaging logic all live inside the vendor's UI.

Cancel, and the playbook leaves with them.

A neutral standard flips that. The playbook can be a folder you own, in your repo, readable by whichever agent wins next year.

We package our own repeatable GTM work this way. The asset that compounds is the folder.

What I'd do this quarter:

1. List the five jobs your team re-explains every week
2. Write each one as a skill: the steps, two real examples, the limit
3. Keep them in your repo and review changes like code
4. Ask every AI vendor one question: can I export my playbook as a skill?

The honest part: a portable format won't fix a bad playbook. And installing a skill means running someone else's instructions. Security guidance is on the foundation's roadmap, so review every skill before you install it.

Own the playbook. Rent the model.

If your AI vendor shut down tomorrow, which part of your playbook would you still own?

### Post
<!-- post:pankaj format:carousel ask:save-this type:news -->
n8n 3 is in pre-release. Do not touch production yet.

3.0.0 landed on October 27 as a pre-release. 3.1.0 followed on November 3. Stable is still on 2.x (2.46.5, shipped today).

If Clay feeds n8n and n8n feeds HubSpot, treat this as a migration of your outbound plumbing.

I read both sets of release notes. Five lines matter for a GTM stack:

1. New API endpoints show dependencies for workflows, credentials and data tables.
2. Unused nodes and Edit Image v1 are removed. The community node API moves to version 3.
3. The chat hub module is off by default.
4. Agents get version history and can publish independently of drafts.
5. The Assistant and MCP can now update credential descriptions.

Number 1 is the quiet win. "Which workflows break if I rotate the HubSpot credential?" finally has an answer.

Number 5 needs a decision. Who, or what, may write to your credential metadata?

The order I'd run it in:

↳ Run the v3 migration report on a copy of your instance
↳ Map credential dependencies before changing anything
↳ Upgrade staging and replay a week of real webhooks
↳ Move production when 3.x goes stable

Honest limit: these are pre-release notes, and nothing is listed for the HubSpot or Salesforce nodes. Test, do not assume.

Upgrades rarely break a stack. Unmapped dependencies do.

Save this before you click update.
