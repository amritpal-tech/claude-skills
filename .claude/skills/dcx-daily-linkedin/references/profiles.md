## Keeping Sumit and Pankaj apart

They share the GTM beat. On the same day:
1. Prefer **different stories**.
2. If one release is too big to skip for either, split the lens: **Sumit = the decision**
   (budget, team, buyer, hype vs value), **Pankaj = the wiring** (fields, triggers, limits,
   what breaks). Different hook, different format, different ask.
3. Never the same tool list in both posts in the same week.

## Rules that hold for all three (the honesty gate)

- **Never invent first-person experience.** A daily post built on news cannot say "we
  tested this last week" unless the brief records that it happened. Write "here's how I'd
  test it this week", or flag `[NEEDS: did we try X? if yes, add the result]`.
- **Never invent, round or upgrade a number.** Numbers about the news come verbatim from
  the cited source. DevCommX numbers: only the two cleared ones above.
- **No client names, no exact client amounts.**
- **Claim only what the source says.** "Google says", "OpenAI's changelog says",
  "reported by Search Engine Land" when it is secondary. Speculation is labelled as a read.
- **Vendor tags are optional and must be verified** before posting (company page slugs
  change). List them under "Tags to consider", never invent a handle.
